# KV-Cache Compression Research — Workflow Spec

This document specifies the working procedure for the engineer driving
the KV-cache compression project. The deliverable is a workshop paper
for **ICML AdaptFM (Resource-Adaptive Foundation Models)**, with the
research question: *under a fixed memory budget per token, which KV-cache
compressor should an inference system deploy?*

## Project state

- Paper draft: `paper.md`
- Reference substrate model: defined in `train.py` (auto-scales per device)
- Eval harness: `evaluate_bpb` in `prepare.py` (read-only) and
  `fast_evaluate_bpb` in `train.py` (4 M val tokens, used for compression evals)
- Compressor zoo: `train.py`, classes inheriting from `KVCompressor`
- Leaderboard: `results.tsv` (one row per experiment)
- Figures: `figures/*.png` regenerated by `uv run figures.py`

## Working procedure (loop until interrupted)

Each iteration:

1. **Critique.** Read `paper.md` and `results.tsv`. Identify the single
   biggest weakness in the current draft — could be a missing baseline,
   an unclear claim, an arithmetic error in the byte-accounting appendix,
   a figure that doesn't actually support the surrounding text, or a
   missing experimental dimension.
2. **Plan.** Translate that weakness into a concrete next experiment OR a
   concrete paper edit. Keep the queue of "next things" in your working
   memory; do not write a separate TODO file.
3. **Implement.** Either:
   - Edit `KVCompressor` / a subclass / `agent_compressor` in `train.py`
     to test a new method, OR
   - Edit `paper.md` to fix the issue, OR
   - Edit `figures.py` to add a new figure, OR
   - Add a new substrate-size config (see "Substrate sweep" below).
4. **Run.** `uv run train.py > run.log 2>&1`. Each run is ~5 min training
   + ~30 s eval on a 4090. If it exceeds 12 min, kill and treat as crash.
5. **Parse.**
   `grep -E "^compression_score:|^compression_ratio:|^val_bpb_delta:|^compressed_bpb:|^compressor_name:" run.log`
6. **Log.** Append a row to `results.tsv` (tab-separated).
7. **Commit.** `git commit -am "<short description of the experiment>"`.
8. **Decide.** If `compression_score` improved over the running max,
   keep the commit. Otherwise `git reset --hard HEAD~1` (the row in
   `results.tsv` is preserved as a `discard` entry).
9. **Refresh figures + paper.** `uv run figures.py`. If the experiment
   meaningfully changes the paper's claims, edit `paper.md` accordingly.
10. Loop.

## Research priorities (in approximate order)

The current draft's biggest weaknesses are:

### A. Narrow compression-family coverage

The leaderboard is currently dominated by quantization variants. Add
substantive entries from each of these families:

- **Token eviction**
  - Sliding window only (no quantization), windows W ∈ {64, 128, 256, 512}
  - Sliding window + attention-sink tokens (StreamingLLM style)
  - Top-k by attention-norm (compute K's row-wise norm, keep top-k)
  - Heavy-hitter retention (H2O-style: cumulative attention scores from
    a calibration pass)
- **Low-rank**
  - Per-(token) SVD of [K | V] truncated to rank r ∈ {8, 16, 32, 48}
  - Cross-layer projection sharing (one projection matrix shared across
    layers — saves on the projection's storage)
- **Head sharing / pruning**
  - Drop heads' K/V entirely (relies on remaining heads for the layer)
  - Cross-layer K-sharing (use layer ℓ's K for layer ℓ+1)
- **Hybrids**
  - Best quantization × best eviction stack
  - Recent tokens at higher precision than old (current best:
    recent-bf16 + old-INT2; explore recent-INT4 + old-INT1, etc.)
  - Per-layer mixed precision (early layers more aggressive than late)

### B. Substrate-scale sweep

The headline finding ("group-wise quantization doesn't help") may be a
small-substrate artifact. Add a sweep at three substrate sizes within
the 24 GB GPU budget — small (DEPTH=3, ASPECT=40), medium (DEPTH=6,
ASPECT=64, current default), large (DEPTH=10, ASPECT=80, batch=8 if
needed). For each compressor that depends on `head_dim` (group-wise
quant especially), report whether the leaderboard ordering changes.

Implementation: parameterize `DEPTH`, `ASPECT_RATIO`, `DEVICE_BATCH_SIZE`
via env vars (e.g. `DEPTH=10 uv run train.py`), with safe defaults if
unset. Record the substrate config in each `results.tsv` row's
description field.

### C. Byte accounting must be airtight

The paper's credibility hinges on the byte counts. Currently the
appendix has hand-wavy arithmetic in places. Make it rigorous:

- For every compressor, write a closed-form expression for *bpt*
  (bytes per token per layer) in terms of `H, D, N, G, R, T, k, ...`.
- Verify the closed-form against the measured `bytes_per_token_per_layer`
  in `results.tsv` to within 1 byte. Any discrepancy → fix the compressor
  or fix the formula.
- Update Appendix B of `paper.md` with the verified table.

### D. Score-α sensitivity

Sweep `COMPRESSION_SCORE_ALPHA` over {10, 20, 50} when computing the
score column in `results.tsv` (or compute all three). Report the leader
under each α. The paper should not depend on a single α.

### E. Figure quality

For each new family added, the existing figures should still convey the
result clearly. Add a family-coloured Pareto plot (`figures/family_pareto.png`).
Add a substrate-scale plot (`figures/substrate_sweep.png`) once that
sweep exists.

## Constraints

### What you CAN do

- Edit `train.py` freely (add new compressor classes, new substrate
  configs, new helpers, new env-var overrides).
- Edit `paper.md`, `figures.py`, `results.tsv`, `program.md` itself,
  `README.md`.
- Run `uv run train.py`, `uv run figures.py`, `uv run prepare.py`.
- `git commit` and `git reset --hard` on the working branch.
- `git push` to back up progress to the remote, and pull at the start
  of each session.

### What you CANNOT do

- Modify the eval logic in `prepare.py` (`evaluate_bpb`,
  `make_dataloader`, `MAX_SEQ_LEN`, `EVAL_TOKENS`, BPE tokenizer,
  data download). The eval is the ground truth. The device-detection
  helper at the top is infrastructure — leave it alone too.
- Install new packages or modify `pyproject.toml` (use what's there).
- Lie about `n_bytes` in `compress()` — every byte must be honestly
  counted (data + scales + zero-points + indices + metadata). A
  compressor that under-reports its bytes is an immediate revert.

## Workflow rules

- **Never ask for permission.** No "should I continue?", no "is this a
  good stopping point?", no "do you want me to try X?", no "shall I
  commit?". Run experiments, edit files, commit. The user is asleep.
- **Never stop voluntarily.** If you run out of priorities A–E,
  re-read the paper, find the next-biggest weakness, and address it.
  The loop runs until manually interrupted.
- **No long mid-loop summaries.** Findings go into `paper.md` and
  `results.tsv`, not into chat output.
- **Preserve discards.** Every experiment, kept or discarded, gets a
  row in `results.tsv`. Do not delete rows. Do not silently skip
  experiments that crash — log them as `crash`.

## Logging format (per row of `results.tsv`)

Tab-separated, header:

```
commit	compression_score	compression_ratio	val_bpb_delta	compressed_bpb	status	description
```

`status ∈ {keep, discard, crash}`. `description` should include the
substrate config when it differs from the default (e.g.
`"sliding window W=128 [DEPTH=10]"`).
